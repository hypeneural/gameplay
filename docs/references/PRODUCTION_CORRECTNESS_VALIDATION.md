# Production-correctness validation against official documentation — 2026-08-23

This addendum validates the production-hardening decisions made after the Game Factory kernel. It uses the installed `phaser@4.2.1` for implementation and official documentation for the public lifecycle contracts.

| Decision                                                 | Official source checked                                                                                                                                                                                                                                                                                                         | Repository consequence                                                                                                                                                                                                                                               |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Phaser destruction is asynchronous                       | Phaser [Game.destroy](https://docs.phaser.io/api-documentation/class/game#destroy) says destruction is scheduled for the next frame and recommends the `DESTROY` event for eventual completion.                                                                                                                                 | `createDevSmokeGame` resolves `GameController.destroy()` only after `Phaser.Core.Events.DESTROY`; the mount coordinator does not allow a new canvas before that promise resolves. `noReturn` remains `false` because the SPA creates another Phaser instance.        |
| Focus and visibility events come from Phaser after boot  | Phaser [Core Events](https://docs.phaser.io/api-documentation/4.0.0/namespace/core-events) documents `HIDDEN`, `VISIBLE`, `BLUR` and `FOCUS` as game visibility-handler events.                                                                                                                                                 | The game relays those signals into the idempotent product run. `PageVisibilityController` is an early-boot fallback for active-duration accounting, not a competing Phaser loop controller.                                                                          |
| Dynamic import chunks can fail after a deployment        | Vite [Build → Load Error Handling](https://vite.dev/guide/build#load-error-handling) documents the `vite:preloadError` event and its prevent-default recovery hook.                                                                                                                                                             | The shell attempts one guarded reload for a stale dynamic game chunk, then exposes the error instead of entering a reload loop.                                                                                                                                      |
| Sharp output is independently observable                 | Sharp [output options](https://sharp.pixelplumbing.com/api-output/#tofile) documents `toFile` output metadata including format and dimensions; [WebP options](https://sharp.pixelplumbing.com/api-output/#webp) documents explicit WebP encoding.                                                                               | A staging directory is publishable only after every `toFile` result is verified as bounded WebP and every expected file exists. Existing derivative directories are rechecked through Sharp metadata.                                                                |
| Media metadata defaults are privacy-friendly             | Sharp [output metadata behavior](https://sharp.pixelplumbing.com/api-output/#keepmetadata) documents metadata stripping and sRGB conversion by default.                                                                                                                                                                         | The worker auto-orients pixels and emits fresh WebP assets without copying source EXIF, XMP or ICC metadata. The corpus inspector records profiles only to inform production policy.                                                                                 |
| Browser-grade run entropy                                | MDN documents [Crypto.getRandomValues](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues_static) and [Crypto.randomUUID](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID_static).                                                                                                      | The browser host creates the run id and deterministic seed with Web Crypto; game domain code still consumes only the injected seeded PRNG.                                                                                                                           |
| Dragging needs a non-drag alternative                    | W3C [Understanding SC 2.5.7 Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) requires a single-pointer alternative unless dragging is essential.                                                                                                                                        | Puzzle Swap's acceptance contract keeps drag but requires tap–tap to perform the same cell swap.                                                                                                                                                                     |
| Phaser drag thresholds can be configured centrally       | Phaser [InputPlugin](https://docs.phaser.io/api-documentation/class/input-inputplugin) exposes `dragDistanceThreshold` and `dragTimeThreshold`.                                                                                                                                                                                 | `TouchProfile` is planned as the single home for initial drag policy; a game may tune it only with viewport evidence.                                                                                                                                                |
| Particle frequency and bursts have distinct semantics    | Phaser [ParticleEmitter](https://docs.phaser.io/api-documentation/class/gameobjects-particles-particleemitter) documents `frequency` and its explode-mode behavior.                                                                                                                                                             | Ambient emission, finite feedback bursts and a win celebration are separate named presets; `LOW` never relies on uncontrolled decoration.                                                                                                                            |
| Filters are not renderer-neutral                         | Phaser [FilterList](https://docs.phaser.io/api-documentation/4.0.0/class/gameobjects-components-filterlist) documents filters as WebGL-only.                                                                                                                                                                                    | Post-FX is an optional enhancement, excluded from the low-quality and reduced-motion acceptance path.                                                                                                                                                                |
| Phaser 4.2.1 fixes relevant responsive/motion defects    | Phaser's official [4.2.1 release notes](https://github.com/phaserjs/phaser/discussions/7333) include the parent-container `ScaleManager` resize fix and Tween `startDelay` transition fix.                                                                                                                                      | The installed 4.2.1 remains pinned. The React shell gives the `RESIZE` host a defined, padding-free parent and future game-feel tweens retain their delay semantics.                                                                                                 |
| Browser history changes URL before an SPA can exit       | MDN [popstate](https://developer.mozilla.org/en-US/docs/Web/API/Window/popstate_event) documents that active history entry/location changes before a listener handles the event; [History API](https://developer.mozilla.org/en-US/docs/Web/API/History_API/Working_with_the_History_API) documents `pushState`/`replaceState`. | The shell uses only `/s/:token` and `/s/:token/game/:gameId`; `runId` stays internal. A `popstate` during play records the destination, requests controller destruction, then commits React route state after the destroy boundary.                                  |
| Tween policy can be calibrated centrally                 | Phaser [Tweens concepts](https://docs.phaser.io/phaser/concepts/tweens) documents easing and staggered tween configuration; the official [4.2.1 release notes](https://github.com/phaserjs/phaser/discussions/7333) fix `startDelay` state advancement.                                                                         | `MotionTokens` owns initial duration/easing values. `FeedbackDirector` remains engine-neutral until Puzzle supplies a scene-local adapter that registers actual tweens in `SceneScope`.                                                                              |
| Game packages remain isolated without blocking internals | dependency-cruiser's [rules reference](https://github.com/sverweij/dependency-cruiser/blob/main/doc/rules-reference.md) documents captured-group matching between `from.path` and `to.pathNot`.                                                                                                                                 | The architecture rule captures a game package id, permits its own domain/runtime imports and rejects only imports to a different game package, including future generated games.                                                                                     |
| One source image can supply all puzzle pieces            | Phaser [Texture](https://docs.phaser.io/api-documentation/class/textures-texture) documents one source with a collection of rectangular Frames; local Phaser 4.2.1 declarations verify the same API.                                                                                                                            | Puzzle Swap loads only the selected `game` variant. Each visible piece uses a deterministic frame on that texture; no per-piece URL or full-resolution original is introduced.                                                                                       |
| Proportional pieces must be real texture frames          | Phaser [Texture](https://docs.phaser.io/api-documentation/class/textures-texture) documents a texture as one source with a collection of frames and `Texture.add(name, sourceIndex, x, y, width, height)` as a rectangular source region. Local Phaser 4.2.1 declarations expose the same signature.                            | Puzzle Swap adds one named proportional frame per source cell to the single run-scoped authorized texture. A piece displays that frame at its cell size; it does not reuse a full-image display scale with a clipping rectangle, and it makes no additional request. |
| Interaction follows Phaser scale geometry                | Phaser's [InputPlugin](https://docs.phaser.io/api-documentation/class/input-inputplugin) documents scene-level pointer events and drag thresholds; [Scale Manager events](https://docs.phaser.io/api-documentation/4.0.0/event/scale-events) documents resize propagation.                                                      | The scene maps pointer coordinates only after its `RESIZE` layout calculation, retains a 16 px initial drag distance and offers the identical swap by tap–tap.                                                                                                       |
| Christmas feedback is finite and scene-owned             | Phaser [Tweens](https://docs.phaser.io/phaser/concepts/tweens) documents scene tween creation and finite tween configuration; [ParticleEmitter](https://docs.phaser.io/api-documentation/class/gameobjects-particles-particleemitter) distinguishes `frequency` from explicit finite explosion mode.                            | Puzzle uses finite sparkle text tweens, not an ambient emitter. Every tween and delayed hint belongs to `SceneScope`; reduced motion omits sparkle emission and `LOW` uses only the policy's small functional burst.                                                 |

## Explicit limits of this validation

- Sharp's local same-filesystem rename protects one writer's publication; it does not establish a distributed queue lease or database transaction.
- The corpus inspector parses every accepted file header but intentionally does not decode/re-encode every candidate. Full worker processing remains the acceptance boundary.
- Vite chunk recovery is a client resilience measure. Deployment cache headers, service-worker lifecycle and reverse-proxy behavior need their own VPS validation before public release.
- The cited Phaser input and particle APIs define available controls; the 52 px child target, 6–8 second assist and first-release threshold values remain product hypotheses to validate with observed child use, not claims made by the API documentation.
